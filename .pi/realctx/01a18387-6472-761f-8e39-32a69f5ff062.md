**Capture stays in Lua**
- Save capture (AD2 CopyEntTable/CopyConstraintTable, PreEntityCopy hooks, EntityMods, Wire/ACF data) must run in Lua on the main thread: these are Lua tables/functions, and rsgdll only touches Lua on the main thread (rsgdll has no engine entity/physics API).
- Only compress/CRC/IO runs on Rust workers.

**Past hang causes** in `lua/autorun/server/gmrecover.lua`:
- `contraption()` called `constraint.GetAllConstrainedEntities` per entity (O(n^2)); fixed with `con_seen`.
- Whole moving contraptions were copied in one tick; fixed: read poses in one tick, copy across ticks, `apply_pose` rewrites PhysicsObjects.

**Native JSON encoder `gmrecover.EncodeJson(tab)`** (replaces `wrap` + `util.TableToJSON` on save)
- Lives in `src/json.rs`. Runs on the main thread, using the raw Lua C API via rsgdll `lua.api()`/`lua.base()`.
- Output must stay readable by `util.JSONToTable` + Lua `unwrap`: `~b` base64 binary, `~s:` key prefix, Vector `"[x y z]"`, Angle `"{p y r}"`, number keys as strings, unsupported values dropped.
- Lua `to_json` uses it when present and falls back to `wrap` + `util.TableToJSON` for old DLLs.
- Profile on a real 5760-entity save before native (Lua time): scan+copy ~1000 ms, wrap ~640 ms, TableToJSON ~1010 ms.
- User priority: save speed matters, restore may lag.

**Coroutine stack crash (ILuaBase ambiguity)**
- `src/json.rs` reads Vector/Angle through ILuaBase (`get_type`/`get_vector`/`pop`) while walking a table with `lua_next`. Saves run inside a Lua coroutine.
- Old code pushed the value, xmoved it to the main stack and popped it with ILuaBase. This crashed srcds (SIGSEGV after `invalid key to 'next'`, a Lua error raised through Rust frames during unwind).
- Probable cause: ILuaBase acted on the coroutine's stack and its pop removed the `lua_next` key.
- Fix: put a copy of the value on top of both stacks, never call ILuaBase pop, and restore both stack tops with `lua_settop`.
- The Lua self-check also encodes Vector/Angle inside a coroutine at load.
